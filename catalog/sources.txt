# abv0 catalog sources
#
# Each line names one upstream project whose official GitHub releases become a
# package in packages/index.json. tools/build-catalog.zig reads this file, finds
# the latest release, picks the right asset for each of abv0's six platforms
# (x86_64/aarch64 x linux/macos/windows), pins its SHA-256 and detects the
# executables inside. A scheduled workflow (.github/workflows/catalog.yml)
# re-runs it, so adding a project here is all it takes to publish it.
#
# Format, one per line:
#
#   name  owner/repo  [key=value ...]
#
#   name                      the abv0 package name (letters, digits, - _ . +)
#   bin=a,b                   executables to expose; replaces detection. The
#                             first one is the primary.
#   asset.<platform>=TEXT     force the release asset whose name is TEXT (an
#                             exact name wins, else the shortest name that
#                             contains it). <platform> is one of
#                             x86_64-linux aarch64-linux x86_64-macos
#                             aarch64-macos x86_64-windows aarch64-windows.
#   skip=<platform>,...       never publish for these platforms
#   desc="..."                replaces the repository description
#   license=SPDX              replaces the repository license
#   tag=<release tag>         pin a release instead of following the latest
#
# Values with spaces go in double quotes. '#' starts a comment. A line that
# cannot be parsed is reported and skipped; it never stops the run.
#
# Software that is not distributed through GitHub releases (a project's own
# download site, or a single script) lives in catalog/manual.json instead.
#
# Only list projects that publish prebuilt binaries as release assets. Whatever
# the picker cannot match (no asset for a platform, an unsupported archive such
# as .bz2 or .7z) simply leaves that platform out.
